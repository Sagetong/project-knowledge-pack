# 虎符安全系统 · 使用说明

> **虎符**：古代的调兵凭证，君王持右半、将军持左半，两半契合才能发兵。
> **这里的两半**：密钥文件（你保管）+ 口令（你记住）。

---

# 一、它保护什么

```
✅ 保护：数据内容
   · 核心安全配置
   · 私密经验（含本机 IP / 路径）
   · 各类密钥

❌ 不保护：代码结构
   · 公开的脚本任何人都能看
   · 工具怎么工作是可以被分析的
```

**⇒ 这是密码学的边界，任何声称"连结构都藏起来"的方案都是在骗你。**

---

# 二、加密构造

```
密钥派生：
   K1 = PBKDF2-HMAC-SHA256(口令, salt, 600000 次, 64 字节)
   K2 = 密钥文件（64 随机字节）
   MasterKey = K1 XOR K2              ← 虎符：缺一不可
   EncKey = MasterKey[0..31]          ← AES-256
   MacKey = MasterKey[32..63]         ← HMAC-SHA256

加密：AES-256-CBC + HMAC-SHA256（encrypt-then-MAC）
      · 先算 MAC，再解密（防 padding oracle）
      · MAC 覆盖 IV + 密文（IV 也被保护）
      · 恒定时间比较（防时序攻击）

文件格式：TALLYv01，固定偏移，手工拼字节
```

**安全强度：**
```
· AES-256  → 穷举不可行
· PBKDF2 60 万次 → 口令暴力破解代价极高
· 双因子   → 单独拿到任何一半都无用
· HMAC     → 任何篡改都会被检出
```

**⇒ 与 7-Zip AES-256 同级或更强。**

# 三、四个命令

## 初始化（只做一次）

```powershell
cd 30-工具\tally
.\init-tally.ps1
```

**它会：**
```
① 提示你设置口令（不显示、不存储）
② 检查口令强度（不够会警告，让你确认）
③ 生成 tally.key ← ★ 虎符右半
④ 派生主密钥（PBKDF2 60 万次，约 3 秒）
⑤ 打包受保护内容
⑥ 加密成 PROTECTED.enc
⑦ 生成 manifest.json
```

## 解锁

```powershell
.\unlock.ps1              # 解密到 WORK\ 目录
.\unlock.ps1 -List        # 只看里面有什么（不落盘）
.\unlock.ps1 -KeyFile <密钥文件>    # 密钥文件在别处
```

## 上锁（用完必须做）

```powershell
.\lock.ps1
```

**它会：**
```
① 重新加密 WORK\ 的内容
② 覆盖写 3 遍 + 删除明文
③ 更新 manifest
④ 清空内存中的密钥
```

## 校验

```powershell
.\verify-tally.ps1           # 浅层：文件完整性 + 安全建议
.\verify-tally.ps1 -Deep     # 深层：实际解密 + 逐文件哈希（需要口令）
```

# 四、⚠️ 三条铁律

## ① 密钥文件必须与包分离存放

```
❌ 错误：PROTECTED.enc 和 tally.key 放在同一个文件夹
        → 有人拿到文件夹就有两半，双因子退化为单因子

✅ 正确：tally.key 放在 U 盘 / 密码管理器 / 加密云盘
        → 攻击者需要同时攻破两个位置
```

**`verify-tally.ps1` 会检查这一点并警告。**

## ② 口令不能忘

```
口令【不存储】在任何地方
忘记口令 = 数据永久丢失
没有任何后门，没有恢复途径
```

**建议：**
```
· ≥ 12 字符，混合大小写 + 数字 + 符号
· 或者：4~5 个不相关词的组合（更长更好记）
· 不要用：生日、姓名、常见词、能在你社交媒体找到的信息
```

## ③ 用完立刻上锁

```
解锁后明文在磁盘上
忘记上锁 = 加密白做
```

**建议：把 `unlock` 和 `lock` 当作一对操作，用完马上 lock。**

# 五、安全边界（诚实说明）

## ✅ 能防住

| 威胁 | 防护 |
|---|---|
| 下载者想看你的私密数据 | 加密，没钥匙看不到 |
| 有人篡改了包 | HMAC 校验，改了必被发现 |
| 密钥文件被单独拿到 | 还需要口令 |
| 口令被单独猜到 | 还需要密钥文件 |
| 口令被暴力破解 | PBKDF2 60 万次 |
| 时序攻击 | 恒定时间比较 |

## ❌ 防不住

| 威胁 | 为什么 |
|---|---|
| 国家级定向破解 | 除非你用足够强的口令 |
| 你的电脑被植入木马 | 解锁后明文在内存/磁盘 |
| 你自己泄露了钥匙 | 社会工程学最难防 |
| 有人 fork 你的公开代码 | 开源的本质 |
| 磁盘取证（未擦净的残留） | 已做 3 遍覆盖写，但 SSD 的磨损均衡无法保证 |

# 六、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `完整性校验失败` | 口令错 / 密钥文件错 / 文件被改 | 检查三种可能 |
| `密钥文件长度错误` | tally.key 损坏或被替换 | 恢复备份 |
| `magic 不匹配` | 不是本系统加密的文件，或文件头损坏 | 从备份恢复 |
| `MAC 长度异常` | 文件损坏 | 从备份恢复 |
| 解密很慢（~3 秒） | PBKDF2 60 万次迭代（这是**特性**） | 正常，迭代次数高才安全 |

# 八、实现中踩过的两个坑（供维护者参考）

**这两个 bug 都是 PowerShell 特有的陷阱，已修复并有测试覆盖。**

## 坑 1：`BinaryWriter` 重载解析不可靠

```
现象：加密后立即解密失败，MAC 校验不通过
诊断：拆解文件头发现 macLen 读出来是 36306（应该是 32）
根因：PowerShell 调用 $bw.Write([uint16]$x) 时重载解析错误，
      导致写入的字节数不对，整个布局错位
修复：放弃 BinaryWriter，改用【固定偏移手工拼字节】
```

## 坑 2：PowerShell 会展开返回的数组

```
现象：1 字节的明文解密后，$result.Length 报"找不到属性"
根因：函数 return 一个【单元素数组】时，PowerShell 会把它
      展开成标量，导致返回类型从 byte[] 变成 byte
修复：所有返回 byte[] 的地方改成 return ,$out（加逗号阻止展开）
```

**⇒ 这两条已记入经验库，避免后人重踩。**

# 九、一句话

> ## **虎符的本质不是"藏起来"，而是"分散风险"——**
> ## **钥匙文件丢了还有口令，口令泄露了还需要钥匙文件。**
>
> ## **而真正的安全边界是：公开的代码任何人都能看，但你的数据只有你能开。**
