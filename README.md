# Experience Pack · 经验包

> ## AI 会忘记，但你的经验不必随它一起消失。

**一个本地优先、可验证、可迁移的 AI 经验包 —— 让你把经过验证的经验，从一个 AI 带到另一个 AI。**

---

## 这是什么

**它解决一个很具体的问题：**

```
你用 AI 解决了一个棘手的问题
        ↓
会话结束 / 上下文被压缩 / 换了另一个 AI
        ↓
这些经验消失了
        ↓
下次遇到同样的问题，你和 AI 都从零开始
```

**Experience Pack 把这件事改成：**

```
AI 解决一个问题
        ↓
把教训写成结构化的一条记录，存进你的文件夹
        ↓
下次任何 AI（不管哪家的）读这个文件夹
        ↓
直接继承这些经验
```

**⇒ 关键区别：这个文件夹在你自己手里，不属于任何 AI 公司。**

---

## 为什么不是"又一个 AI 记忆库"

**市面上已经有很成熟的 AI 记忆方案**（例如 mem0、Letta、Zep 等）。它们解决的是「让 AI 记得你」。

**这个项目解决的问题不一样。**

| | 典型的 AI 记忆方案 | Experience Pack |
|---|---|---|
| **数据在哪** | 平台方的云数据库 | **你的本地文件夹** |
| **属于谁** | 平台 | **你自己** |
| **能带走吗** | 通常不能 | **拷贝文件夹即可** |
| **换个 AI 还能用吗** | 通常不能 | **能 —— 它只是一个文件夹** |
| **能验证没被改过吗** | 一般不能 | **能（数字签名）** |
| **存的是什么** | 偏好、事实、对话摘要 | **可复用的"教训"（含情境、错误、解法）** |

**⇒ 一句话：它不追求"更聪明的记忆"，它追求「经验是一种你能拥有、能检查、能带走的资产」。**

---

## 它从哪来（这可能是最重要的部分）

**它不是先设计好一个框架，然后找场景套用。**

**它是一个真实项目的副产物：**

```
想做一个"能真正在 Windows 上执行任务的本地 AI Agent"
        ↓
过程中遇到大量具体问题：
   · 多个 AI 怎么协同？谁动手、谁记录？
   · 上下文丢了怎么办？
   · AI 把假设当成事实怎么办？
   · 我怎么知道它的判断是对的？
   · 开源出去的包，怎么防止被别人的东西污染？
        ↓
每解决一个问题，就把教训结构化地记下来
        ↓
记着记着，它变成了一套体系
```

**⇒ 所以这份包里的经验条目，全部来自真实踩过的坑，不是编出来的方法论。**

**它回答的是「AI 真的干活时会遇到什么」，而不是「理论上应该有什么功能」。**

## 运行环境（前置条件）

**下面这些是**实测确认过**的要求。都不需要另外安装。**

| 需要什么 | 版本 / 位置 | Windows 自带吗 |
|---|---|---|
| **Windows** | 10 或 11 | — |
| **Windows PowerShell** | **5.1 或更高** | ✅ **自带**（`C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`）|
| **OpenSSH 客户端** | 用于验签 | ✅ **Windows 10 1809+ 自带**（`C:\WINDOWS\System32\OpenSSH\ssh-keygen.exe`）|

**⚠️ 关于执行策略：**

```
Windows 默认的执行策略通常是 Restricted（禁止运行脚本）。
本项目所有示例命令都带 -ExecutionPolicy Bypass，
所以【不需要】你修改系统执行策略。

如果你手工直接双击 .ps1，可能会被挡住 —— 请按 README 里的命令形式调用。
```

**⚠️ 关于目录位置：**

```
包必须放在【可写】的目录里（因为写入经验要创建/修改文件）。
不要把包放在：
   · 只读位置
   · 受系统保护的目录（如 C:\Program Files\ 下）
   · 正在被云盘实时同步的目录（可能产生写入冲突）
```

**⚠️ 如果你在非 Windows 系统上：**

```
数据部分（.md / .jsonl）是纯文本，任何系统都能读。
验签用的是标准 OpenSSH 命令，Linux / macOS 上的写法相同：
   ssh-keygen -Y verify -f allowed_signers -I tally-author@SageTong \
              -n file -s core-manifest.txt.sig < core-manifest.txt
但工具脚本（30-工具\*.ps1）目前只在 Windows PowerShell 5.1 上验证过。
```

> **v0.1 是 Windows 优先的。**非 Windows 用户目前只能读取数据（数据是纯文本），工具层需要改写。

### 如果你是人

```
1. 把整个文件夹复制到任意位置
2. 想了解它 → 读 00-底层逻辑\ARCHITECTURE.md
3. 想用它   → 需要一点 PowerShell 基础，见 10-说明书\FOR-HUMAN.md
```

> **⚠️ v0.1 的诚实说明：目前还没有"双击安装程序"。**
> 工具是 PowerShell 脚本（`30-工具\*.ps1`），需要手工运行。
> "零命令行"是设计目标，正在做，但**现在还不是**。
> 我们宁愿在这里说清楚，也不愿意让你下载完才发现。

### 如果你是 AI

```powershell
cd 30-工具
.\memory.ps1 context      # 拿到一份项目记忆简报
```

**⚠️ 关于 `context` 的真实规模（实测数据，不夸大）：**

| 项 | 实测值 |
|---|---|
| 包在磁盘上的大小 | 约 576 KB |
| `context` 输出的实际大小 | **约 65 KB（≈ 2.5 万 ~ 3.1 万 token）** |
| 相对原始数据的压缩比 | 约 63% |

**⇒ 它不是"把 576 KB 全塞给你"，而是筛出一份简报。**
**但 65 KB 也不算小 —— 上下文窗口有限的模型需要留意这个量。**
**⇒ 改进方向是分主题按需检索，而不是一次给全部。这件事还没做。**

**然后读：**
- `10-说明书\AGENTS.md` —— 工作规范（AI 行为准则）
- `10-说明书\FOR-AI.md` —— 使用指南

### 📋 命令退出码的含义（避免把正常状态误判为故障）

| 退出码 | 含义 | 常见于 |
|---|---|---|
| **0** | 成功 | 所有命令 |
| **1** | 执行完成，但发现了问题或前置条件不满足 | `tally\verify-tally.ps1`（尚未初始化虎符）、`verify-core.ps1`（检测到篡改或缺失） |
| **2** | 参数或路径错误 | 传入不存在的目录 |

**⇒ 特别说明：在一个**全新拿到的包**里运行 `90-虎符v2\verify-core.ps1`：**

```
可能看到 [缺失] 或 [篡改] 提示
```

**这不一定是包坏了。原因：**

```
core-manifest.txt 里的哈希，是在【作者签名那一刻】计算的。
如果你拿到的包之后被任何人改过任何一个核心文件，
验签就会报"篡改"—— 这正是它该有的作用。

但如果你刚下载、什么都没改，却报"篡改"，
那就是真的有问题（或者签名已经过期）。请开 Issue。
```

**⇒ 同理，`30-工具\tally\verify-tally.ps1` 在没有任何虎符密钥的新包里报"文件缺失，无法校验"（退出码 1），
这是**正常的初始状态**，不是包损坏。虎符体系需要使用者自己初始化。**

## 三个核心概念

### ① 三层命名空间 —— 让"本机隐私"和"可分享知识"分开

```
20-历史经验\data\
   ├─ local\          只属于这台机器（IP、路径、配置）   ← 绝不外传
   ├─ universal\      抽象出的通用知识                  ← 可以分享
   └─ contributed\    别人给我的经验（隔离区）           ← 先进隔离，验证后提升
```

**流动方向是单向的：**

```
local（本机）
   ↓  验证它确实有普适性
promote 提升
   ↓
universal（通用）
```

**⇒ 这样你可以放心地每天往里写东西 —— 因为私密的部分永远不会被带出去。**

**⚠️ 但这句话必须说得精确：这是「流程保证」，不是「技术强制」。**

| 说法 | 准确吗 |
|---|---|
| ~~本机数据在技术上不可能外泄~~ | ❌ **不对**。文件就在那里，谁都能复制 |
| **有一套固定的发布流程，会自动剔除本机层；本项目已实测验证** | ✅ **准确** |

具体做法：本项目有一个 `sync-to-release.ps1`，它会把本机层清空、把可识别的个人信息脱敏、然后重新生成清单。**流程后的成品经过独立扫描确认零残留。**
**但如果你不走这个流程、直接把文件夹发出去，本机层就会一起发出去。**

### ② 状态分级 —— 防止"把假设当事实"被继承下去

**每条事实必须标注它的可信度：**

| 状态 | 含义 | 能否作为决策依据 |
|---|---|---|
| `verified` | 有证据 | ✅ 可以 |
| `hypothesis` | 合理推断 | ❌ **不可以** |
| `unverified` | 待实测 | ❌ 不可以 |
| `falsified` | 已证伪 | ❌ **不要再提** |

**⇒ 为什么重要：如果没有这一层，一条错误的假设会被后续所有 AI 当成事实继承，错误会越滚越大。**

**真实案例（来自本项目）：**

| 当时的判断 | 标记 | 后来 |
|---|---|---|
| "某云服务商的 IP 会被 OpenAI 封" | ⚠️ hypothesis | **实测证伪**，标为 falsified |
| "把某配置项改成 X 就没问题" | ⚠️ hypothesis | **实测证伪**，写进了经验库 |

**⚠️ 关于 `verified` 的诚实说明（这一条很重要）：**

**目前 `verified` 的标准是「**作者本人实测过，并把证据写进了 `evidence` 字段**」。**

**它**不是**：**
- ❌ 第三方独立复现过
- ❌ 有形式化的证据要求
- ❌ 会随时间自动过期
- ❌ 与具体的 Windows 版本 / 模型版本绑定

**⇒ 所以现在的状态标签，本质上是「作者的主观标注 + 附了证据」，
而不是「经过独立审计的事实」。**

**⇒ 这已经比"不标注"好得多（至少假设不会被当成事实继承），
但距离"可信的证据机制"还有距离。这是我们想改进的方向。**

### ③ 信任层 —— 经验是谁写的、有没有被改过

**这是这个项目比较少见的部分：把「可验证性」加到了个人经验上。**

```
核心清单 core-manifest.txt
    ↓  用作者私钥签名（Ed25519）
core-manifest.txt.sig
    ↓  连同公钥清单一起发布
allowed_signers
```

**任何人都可以验证：**

| 情形 | 结果 |
|---|---|
| 文件没被改过 | ✅ 通过 |
| 文件被改过 | ❌ 检出 |
| 别人冒充作者签名 | ❌ 拒绝 |

**⚠️ 诚实的边界：**

**自签自验证明的是「这份内容和这把公钥对应」，**
**而不是「这个作者在现实世界里是谁」。**

**⇒ 所以我们说它是「可验证完整性与来源一致性」，不提"绝对可信"。**

**⚠️ 另外两点必须说清：**

**① 签名证明完整性，不证明内容无害。**
一份**有合法签名**的经验条目里，也可能含有针对 AI 的恶意指令（提示注入）。
⇒ 所以对来自 `contributed\`（外部贡献）的内容，**不要无条件信任**。
这也是为什么要把它隔离在单独一层，而不是直接进 `universal\`。

**② 公钥怎么确认是作者的？**
目前 `allowed_signers` 是随包一起发布的。
⇒ 这意味着它只能证明「**包里的内容与包里的公钥一致**」，
不能证明「**这把公钥真的属于某个具体的人**」。
⇒ 要解决这个问题需要外部可信渠道（例如把公钥指纹发布在别处供对照），**本项目还没做**。

### ④ 加密体系（"虎符"）—— 把保证范围写准确

**它有两半，各自解决不同的问题：**

**左半 · 用户口令锁（保护你自己的私有数据）**

```
双口令（v3）:    MasterKey = K1 XOR K2
                ⇒ 两个都要有，缺一不可

三选二（v3.1）:  为每一组口令配对派生一个密钥
                  K_12 = PBKDF2(左符||口令1||口令2, salt, 600000)
                  K_13 = PBKDF2(左符||口令1||口令3, ...)
                  K_23 = PBKDF2(左符||口令2||口令3, ...)
                用这三个密钥分别加密同一个真密钥:
                  vault-12 = AES(K_12, REAL_KEY)
                  vault-13 = AES(K_13, REAL_KEY)
                  vault-23 = AES(K_23, REAL_KEY)
                ⇒ 任意两个口令能打开对应的那一个保险箱，拿到真密钥
```

**⚠️ 精确说明（这几句很重要）：**

| 说法 | 准确吗 |
|---|---|
| 这是 2-of-3 门限 | ✅ 是（用「配对保险箱」构造，不是 Shamir 秘密分享，但同样正确） |
| ~~这是多因素认证~~ | ❌ **不是**。三个口令都属于「你知道的东西」，严格说是同一类因素 |
| ~~PBKDF2 600k 次就代表数据安全~~ | ❌ **不是**。迭代次数只是**提高暴力破解的成本**，它本身不等于加密强度。数据是否安全，取决于真密钥有没有被正确保护 |

**右半 · 作者签名（证明核心出处）**

见上面第 ③ 节。

**⇒ 合起来，它做了两件**有限但明确**的事：**
1. **让你的私有数据不是明文放在那里（有口令锁）**
2. **让别人能发现核心文件有没有被改过（有签名）**

**⇒ 它**没有**做的：防住拿到你电脑的人、防住你口令本身泄露、防止有签名的内容里含有恶意指令。**

## 现在能做什么 / 还不能做什么

### ✅ 已经能用的

- AI 把解决过的问题写成结构化经验（含情境 / 错误 / 解法 / 可复用结论）
- 任何 AI 一条命令读取全部上下文
- 本机 / 通用 / 外部贡献三层隔离
- 事实带可信度分级
- 核心内容数字签名（Ed25519）
- 历史记录哈希链 + 签名锚点
- 完整性校验（SHA256 清单）
- 全流程可在 Windows 上运行（PowerShell 脚本）

### ❌ 还没有的（不假装有）

| 缺什么 | 说明 |
|---|---|
| **效果证据** | **我们证明了"经验能保存"，但还没系统证明"它能让你少走多少弯路"** —— 这是 v0.2 最想做的事 |
| **跨平台** | 目前是 Windows + PowerShell。数据格式是跨平台的，工具层不是 |
| **自动检索** | 现在是全文匹配，没有向量检索 / 语义搜索 |
| **安装程序** | 现在是"复制文件夹 + 跑 PowerShell 脚本"，还没有双击安装包 |
| **多人协作流程** | 已留位置和规则，但还没有真实的外部贡献者 |

**⇒ 我们刻意把"还没做的"写在这里。一个诚实列出缺点的项目，比一个声称啥都行的项目更值得信任。**

### 一条重要的安全规则

> ## **别人的经验可以进来，别人的框架不可以进来。**

| 层 | 合并时的行为 |
|---|---|
| 核心层（`00-底层逻辑\`、`30-工具\`）| **工具拒绝覆盖**，保留原作者版本 |
| 共享层（`universal\`、`10-说明书\`）| 可自由合并 |
| 贡献层（`contributed\`）| 只追加，署来源 |
| 本地层（`local\`、`50-环境档案\`）| **不参与外发** |
| 史书层（`70-文明史书\`）| 只追加 |

**⇒ 目的：避免作者在合并别人的经验包时，核心被污染、变成攻击面。**

**⚠️ 但这里必须说实话：「拒绝覆盖」是**工具的行为**，不是**技术上的强制**。**

| 说法 | 准确吗 |
|---|---|
| ~~别人的东西在技术上不可能覆盖核心~~ | ❌ **不对**。文件是普通文件，手工复制粘贴当然能覆盖 |
| **合并工具会拒绝覆盖核心；如果被改过，签名验证能发现** | ✅ **准确** |

**⇒ 换句话说，这条规则提供的是「**阻力 + 可检测性**」，不是「不可突破的墙」。**
**对个人项目来说这已经够用（能防住误操作和普通污染），但要诚实说明它的边界。**

## 数据格式

**用 JSONL（一行一条 JSON）。为什么不用别的：**

| 格式 | 追加安全 | 机器可解析 | 人可读 |
|---|---|---|---|
| **JSONL** | ✅ 加一行 | ✅ | ✅ |
| 单个 JSON | ❌ 要重写整个文件 | ✅ | 🟡 |
| SQLite | ✅ | ✅ | ❌ 需要驱动 |

**⇒ 详细定义见 `SCHEMA.md`。**

**四条数据线：**

| 文件 | 存什么 | 关键字段 |
|---|---|---|
| `facts.jsonl` | 事实 | claim / status / evidence |
| `lessons.jsonl` | 教训 | title / context / mistake / solution / reusable |
| `decisions.jsonl` | 决策 | question / chosen / rejected / reason |
| `timeline.jsonl` | 时间线 | event / detail / actor |

## 编码约定（踩过坑，写下来）

| 文件类型 | 编码 | 为什么 |
|---|---|---|
| `*.ps1` | **UTF-8 with BOM** | PowerShell 5.1 不加 BOM 会把中文读成乱码 |
| `*.md` | **UTF-8 无 BOM** | 开源标准 |
| `*.json` | **UTF-8 无 BOM** | JSON 规范要求；带 BOM 会让 Python 等解析器直接报错 |
| `*.jsonl` | **UTF-8 无 BOM** | 同上；带 BOM 还会让按行解析静默跳过第一行 |
| `*.cmd` | **纯 ASCII** | 含中文会乱码 |

**⇒ 这些不是理论，是踩坑换来的。**
