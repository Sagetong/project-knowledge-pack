# 二、将来必须解决的四个问题

**在启用本目录之前，这些问题必须有答案。**

## 问题 1：怎么保证质量

```
1000 条提交里可能只有 50 条有价值
```

**需要定义：**
- 什么样的经验可以提交（有具体症状 + 可复现步骤）
- 什么样的经验会被拒绝（太模糊、太具体、无解法）
- 质量评分机制

## 问题 2：怎么防止投毒

```
恶意提交错误经验 → 污染所有下游使用者
```

**需要定义：**
- `contributed\` 命名空间 = 隔离区（不直接影响决策）
- 提升到 `universal\` 需要什么条件
- 是否需要签名

## 问题 3：怎么抽象通用性

```
"我的防火墙规则" 不可分享
"网络问题先开日志" 可以分享
```

**需要定义：**
- 判定标准（见 `SCHEMA.md` 第四节的命名空间规则）
- 谁来抽象（提交者？审核者？自动工具？）
- `promote.ps1` 已提供工具支持

## 问题 4：怎么合并多个来源

```
使用者 A 的经验包 + 使用者 B 的经验包 → 合并
```

**需要定义：**
- id 冲突怎么办（不同包可能有相同 id）
- 矛盾经验怎么标记
- 去重策略

**已有基础**：`origin` 字段（见 `SCHEMA.md` 第 4.6 节）

# 三、现在该做什么

**理由：**
```
① 数据量不够 —— 只有 90 条经验，无法验证协议是否合理
② 没有第二个使用者 —— 不知道真实需求
③ 容易过度设计 —— 设计出来的东西大概率不适用
```

```
① 继续积累 local 经验（目标 100+ 条）
```
