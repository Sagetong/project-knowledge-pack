# 架构总览：三个本地 AI 的协作闭环

> **这是本项目最终成型的架构。**
> **回答一个问题：手机 GPT、电脑上的三个 AI、Windows 电脑，它们之间怎么协作？**

**最后更新**：2026-10-06 20:20

---

# 一、核心洞察（用户的贡献）

**问题**：GPT 模型本身无法访问你的电脑（实测证实：零公网来源请求）。

**用户的解法**：
```
GPT 不能"被调用"，但它说的话【会出现在桌面上】

   手机 GPT 聊天
        ↓ 云端同步
   桌面 GPT 显示历史
        ↓
   ★ 这就是一条单向的数据通道 ★
```

**⇒ 不需要 GPT 有任何"被调用"的能力，只需要它能显示文字。**

---

# 二、四条真实存在的通路

| # | 通路 | 发起者 | 状态 | 跨网络 |
|---|---|---|---|---|
| **A** | 手机浏览器 → 8788 | 浏览器 | ✅ 实测 | ❌ 同 WiFi |
| **B** | 手机 AA App → 电脑 | AA App | ✅ 活跃 | ✅ 能 |
| **C** | 桌面 GPT 界面 → 截图 → Codex 视觉 | 本地 AI | ✅ **实测** | N/A |
| **D** | 手机 GPT 直接调电脑 | — | ❌ **不可能** | — |

**⇒ D 不存在。A/B 是入口，C 是"读取 GPT 意图"的通道。**

# 三、完整链路

```
┌─────────────────────────────────────────────────────────────┐
│  你的操作                                                    │
├─────────────────────────────────────────────────────────────┤
│  ① 在手机 GPT 里说出你的想法/目标                            │
│  ② 在手机 AA App 里对我（DeepSeek）说：                      │
│        "看一下我 GPT 里刚说的，然后去做"                     │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  我（DeepSeek / DSH）—— 编排者                               │
├─────────────────────────────────────────────────────────────┤
│  read-desktop-gpt.ps1                                        │
│     ├─ 定位并激活 ChatGPT 窗口                               │
│     ├─ 截图                                                   │
│     └─ 交给 Codex 视觉读取 → 拿到你 GPT 里的内容             │
│                                                              │
│  理解意图 → 决定怎么分工                                      │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  delegate.ps1 —— 分派器                                      │
├─────────────────────────────────────────────────────────────┤
│  -To codex    → GPT-6 执行（强推理、可操作电脑）             │
│  -To qwen     → 千问执行（交叉验证、另一视角）               │

                            ↓
┌─────────────────────────────────────────────────────────────┐
│  执行结果汇总 → 回传给你                                      │

```

# 五、关键工具

| 工具 | 位置 | 作用 |
|---|---|---|
| **read-desktop-gpt.ps1** | `agents\bridge-client\` | ★ 截图桌面 GPT → Codex 视觉读取 |
| **delegate.ps1** | `agents\bridge-client\` | ★ 把任务派给 Codex / 千问 / DeepSeek |
| **memory.ps1** | `experience-pack\30-工具\` | 读经验库 |
| **harvest.ps1** | `experience-pack\30-工具\` | 写经验库（自动同步桌面） |
| **sync-pack.ps1** | `experience-pack\30-工具\` | 经验包镜像同步 |

**调用示例：**
```powershell
# 读 GPT 界面
.\read-desktop-gpt.ps1 -Question "左侧历史列表有什么？"

# 派任务
.\delegate.ps1 -To codex -Task "分析 <项目盘> 的目录结构"
.\delegate.ps1 -To qwen  -Task "解释这段代码"
.\delegate.ps1 -Fanout   -Task "同一个问题问三个 AI"
```

# 六、⚠️ 已知限制

| 限制 | 说明 | 可能的改进 |
|---|---|---|
| **桌面 GPT 窗口必须在屏幕内** | 窗口跑到屏幕外时截图会失败 | 工具已内置检测，但需要先手动唤起一次 |
| **截图读取有延迟** | 19-24 秒 | 只截必要区域可提速 |
| **Codex 只能用 bypass 沙箱** | 无沙箱无审批 | 装 git 可解锁 workspace-write |
| **手机浏览器只能同 WiFi** | 8788 是局域网地址 | 走 AA 可跨网络 |
| **Fanout 子进程编码** | 已用"结果写文件"绕过 | — |
| **含中文的 .ps1 必须有 BOM** | 否则 `-File` 执行时按 GBK 解码 | 写入后补 BOM |

# 七、这个架构的价值

**对比"传统做法"：**

| | 传统 | 本架构 |
|---|---|---|
| **GPT 的角色** | 需要被"接入"（MCP/插件/API） | 只需显示文字 |
| **依赖** | 平台开放能力 | 屏幕像素 |
| **可行性** | 受账号权限限制 | ✅ 已实测可用 |
| **跨平台** | 各平台不同 | 只要能看到界面就行 |

**⇒ 核心优势：不依赖任何平台的"开放接口"，用最原始的方式（看屏幕）实现跨 AI 协作。**
