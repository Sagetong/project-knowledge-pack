# 虎符安全系统 · 架构设计

> **设计目标**：经验包公开给世界，但**核心的东西只有作者能开**。
> **设计原则**：只承诺密码学上真正能做到的事，不制造虚假的安全感。
> **状态**：设计阶段，待用户确认后实现。

**版本**：0.1（设计稿） · **日期**：2026-10-06

# 一、先说清楚：什么能做到，什么做不到

**这是本文最重要的一节。任何安全方案如果不先划清边界，就是在骗人。**

## ✅ 密码学上能做到的

| 能力 | 原理 | 强度 |
|---|---|---|
| **没钥匙看不到内容** | AES-256 加密 | 穷举不可行 |
| **必须同时有两样东西** | 虎符双因子（文件 + 口令） | 缺一不可 |
| **别人改了能发现** | 签名 / 哈希链 | 任何改动都会暴露 |
| **能验证"这是官方版本"** | 作者公钥签名 | 无法伪造 |
| **能控制什么公开、什么私有** | 分层 + 加密边界 | 由你决定 |

## ❌ 做不到的（如果有人承诺，那是骗你）

| 做不到的事 | 为什么 |
|---|---|
| **阻止别人看到"结构"** | 代码开源 → 结构就公开了。**只有内容能加密** |
| **阻止别人复制公开部分另搞一套** | 这是开源的定义 |
| **让公开代码"不可修改"** | 别人可以 fork，只是不能冒充你的官方版 |
| **保护已经明文运行过的数据** | 内存、临时文件、日志都可能残留 |
| **防止有钥匙的人泄露** | 如果你自己被钓鱼，钥匙就丢了 |
| **"安装后就无法破解"** | 只有"没有钥匙就解不开" |

## ⚠️ 需要你理解的关键概念

```
【加密保护的是"数据"，不是"代码逻辑"】

如果你的核心逻辑是 PowerShell 脚本，别人能看到它怎么工作。
只有当你把【数据/配置/密钥】加密时，"看不到内容"才成立。

⇒ 所以核心问题不是"怎么把代码藏起来"，
  而是"哪些东西必须加密，哪些可以公开"。
```

# 二、虎符的隐喻与实现

## 古代的虎符

```
君王持右半   将军持左半
       ↓
  两半契合 → 才能调动军队
       ↓
  只有一半 → 无效
```

## 我们的实现

```
虎符右半：密钥文件（tally.key）      ← 你保管，放在安全位置
虎符左半：口令（你记住）              ← 不落盘，只在脑子里
       ↓
   两者结合 → 派生出解密密钥
       ↓
   缺任何一半 → 无法解密
```

## 技术细节

```
① 初始化时：
   生成随机盐 salt (32 字节)
   生成随机密钥文件 keyfile (32 字节)  → 存为 tally.key
   用户设置口令 passphrase              → 不存

② 派生密钥：
   K1 = PBKDF2(passphrase, salt, 600000 次, 32 字节)
   K2 = keyfile (32 字节)
   MasterKey = K1 XOR K2                ← 必须两者都有

③ 加密：
   用 MasterKey 做 AES-256-GCM 加密核心文件
   GCM 自带完整性校验（改了会解密失败）

④ 解锁：
   输入口令 + 提供 tally.key → 重算 MasterKey → 解密
```

**为什么是 XOR + PBKDF2 而不是更复杂的方案？**

```
· PBKDF2 让口令难以暴力破解（60 万次迭代）
· XOR 让两个因子都必须正确（任一错误 → 密钥全错）
· AES-GCM 同时提供机密性 + 完整性
· 简单 = 容易验证 = 更安全（复杂方案更容易有实现漏洞）
```

# 三、分层架构

## 3.1 三层结构

```
experience-pack\
│
├─ 【公开层】PUBLIC\ ················· 开源出去的部分
│    ├─ README.md                    整体说明
│    ├─ SCHEMA.md                    数据格式（贡献者必须读）
│    ├─ 10-说明书\                   怎么用
│    │    ├─ FOR-AI.md
│    │    ├─ FOR-HUMAN.md
│    │    └─ AGENTS.md
│    ├─ 00-底层逻辑\                 设计原理
│    │    ├─ ARCHITECTURE.md
│    │    └─ GROWTH-MODEL.md
│    ├─ 40-Skills\_template\         Skill 模板
│    ├─ 30-工具\  (接口说明)          工具的【用法】，不含核心实现
│    │    └─ INTERFACE.md
│    └─ 20-历史经验\universal\       可公开的通用知识
│
├─ 【受保护层】PROTECTED.enc ········· ★ 加密后的整体
│    （以下内容加密后打包成这一个文件）
│    ├─ core\                        ★ 核心配置与安全设置
│    │    ├─ security.json           安全策略
│    │    ├─ keys\                   各类密钥
│    │    └─ config.json             核心参数
│    ├─ local\                       私密经验（含本机信息）
│    └─ tools\                       工具的【核心实现】
│
└─ 【虎符】tally\ ····················· ★ 解锁凭证
     ├─ tally.key                    密钥文件（虎符右半）★ 你保管
     ├─ salt.bin                     盐
     ├─ manifest.json                加密清单 + 校验值
     └─ README.md                    使用说明
```

## 3.2 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| **加密粒度** | 整体打包加密 | 简单、不漏单个文件 |
| **公开什么** | 说明书 + 框架 + 模板 | 别人靠这个才能用 |
| **藏什么** | 核心配置 + 私密数据 + 关键实现 | 这些泄露才有实际损失 |
| **虎符存哪** | `tally.key` 单独放（建议 U 盘/云盘） | 与加密文件分离 |
| **口令存哪** | **不存** | 只在脑子里 |

| **本机经验（local）** | | ✅ | 含 IP/路径，泄露有风险 |
| **核心安全配置** | | ✅ | 这是"虎符"要保护的东西 |

| **工具的完整实现** | 🟡 | 🟡 | 见下方讨论 |
| **成长模型 GROWTH-MODEL** | ✅ | | 展示愿景，吸引参与者 |

## 关于「工具实现」要不要公开的讨论

```
选项 A：工具全部公开
   优点：别人能直接用、能改进、能审查安全性
   缺点：核心逻辑被看到

选项 B：工具核心加密，只公开接口
   优点：核心逻辑受保护
   缺点：别人无法使用（除非你给他们解密）
        ⇒ 这就失去了开源的意义

选项 C（推荐）：工具公开，但【安全相关配置】加密
   优点：别人能用工具，但你的密钥/策略/私密数据受保护
   缺点：工具逻辑公开

⇒ 我的建议是 C。
  原因：工具的价值在于"能被使用"，藏着就没意义了。
       真正需要保护的是"你的数据"和"你的密钥"，不是"工具怎么写的"。
```

# 五、威胁模型（防谁，不防谁）

**安全方案必须明确假想敌。否则就是空谈。**

## ✅ 能防住的

| 威胁 | 防护方式 |
|---|---|
| **好奇的下载者想看你的私密数据** | 加密，没钥匙看不到 |
| **有人篡改了包的内容** | 签名/哈希校验，能发现 |
| **有人冒充官方版本发布** | 你的公钥签名，无法伪造 |
| **密钥文件被单独拿到** | 还需要口令（虎符的另一半） |
| **口令被猜到** | PBKDF2 60 万次迭代，暴力破解不可行 |
| **加密文件被单独拿到** | 还需要 tally.key |

## ❌ 防不住的

| 威胁 | 为什么防不住 |
|---|---|
| **国家级攻击者定向破解** | 除非你用了足够强的口令 |
| **你的电脑被植入木马** | 解锁后明文就在内存里 |
| **你自己泄露了钥匙** | 社会工程学最难防 |
| **有人 fork 你的公开部分** | 开源的本质 |
| **有人逆向你的公开工具** | 公开就意味着可分析 |

# 七、使用流程（预期）

## 初始化（只做一次）

```powershell
cd 30-工具\tally
.\init-tally.ps1
# 提示你设置口令（不会显示，不会存储）
# 生成 tally.key ← ★ 立刻备份到安全位置！
# 加密受保护层 → PROTECTED.enc
# 删除明文（可选）
```

## 日常使用

```powershell
# 解锁
.\unlock.ps1
#   输入口令 + 指定 tally.key 路径
#   → 解密到临时目录（内存或受保护目录）
#   → 或者直接解密到工作目录

# 工作时用解锁后的内容

# 上锁
.\lock.ps1
#   → 重新加密 → 删除明文
```

## 验证完整性

```powershell
.\verify-tally.ps1
#   → 检查 PROTECTED.enc 是否被篡改
#   → 检查签名是否有效
```

# 八、⚠️ 关键警告

## 关于口令

```
· 口令【不会】被存储在任何地方
· 忘记口令 = 数据永久丢失（无法恢复）
· 建议：用你记得住但别人猜不到的短语，至少 12 个字符
· 不要用：生日、姓名、常见词、你能在社交媒体找到的信息
```

## 关于 tally.key

```
· 这是虎符的另一半，必须与加密文件【分开存放】
· 建议：U 盘 / 密码管理器 / 加密云盘
· 不要：和 PROTECTED.enc 放在同一个文件夹（那等于没有双因子）
· 一旦丢失 + 忘记口令 = 数据永久丢失
```

## 关于本方案的真实强度

```
✅ 强于：不加密、简单压缩包加密、混淆代码
✅ 等同于：标准文件加密方案（7-Zip AES-256 同级或更强）
❌ 不等于：硬件安全模块(HSM)、军规级保密
⚠️ 关键变量是【你的口令强度】，不是算法
```

# 十、一句话

> ## **虎符的本质不是"藏起来"，而是"分散风险"——**
> ## **钥匙文件丢了，还有口令；口令泄露了，还需要钥匙文件。**
>
> ## **而真正的安全边界是：公开的代码任何人都能看，但你的数据只有你能开。**
